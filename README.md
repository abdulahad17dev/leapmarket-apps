# Каталог LeapMarket

Сервер магазина — обычный публичный репозиторий на GitHub:

| Что | Где лежит | Зачем |
|---|---|---|
| `apps.json` | в ветке `main` | список приложений, его читает магазин |
| `icons/` | в ветке `main` | иконки, по одной на пакет |
| `*.apk` | в **Releases**, тег `apps` | сами файлы приложений |

APK держим в релизах, а не в репозитории: в репозиторий нельзя класть файлы
больше 100 МБ, а в релиз можно до 2 ГБ. Репозиторий должен быть **публичным** —
иначе `raw.githubusercontent.com` потребует токен, а магазин его не передаёт.

## Первая настройка

1. Создать на GitHub публичный репозиторий, например `leapmarket-catalog`.
2. Сложить APK в папку `apks/` в проекте.
3. Собрать каталог:

   ```
   python tools/build_catalog.py --repo ВАШ_ЛОГИН/leapmarket-catalog
   ```

   Скрипт прочитает каждый APK, возьмёт оттуда пакет, версию, `versionCode`
   и название, достанет иконку и запишет `catalog/apps.json`.

4. Если для какого-то приложения написано «нужна иконка» — внутри APK иконка
   нарисована вектором, картинки там нет. Положите PNG 192×192 в
   `catalog/icons/<пакет>.png` и запустите скрипт ещё раз: свои иконки он
   не перезаписывает.
5. Поправить в `catalog/apps.json` названия и описания — они попадут в магазин
   как есть. Скрипт их запоминает и при следующих запусках не затирает.
6. Залить в репозиторий: `apps.json` и папку `icons/` — в ветку `main`.
7. Создать релиз с тегом **`apps`** и приложить к нему все `.apk`.
8. В приложении открыть `app/src/main/java/com/rt/leapmarket/data/RemoteApp.kt`
   и указать свой репозиторий:

   ```kotlin
   private const val REPO = "ВАШ_ЛОГИН/leapmarket-catalog"
   ```

9. Пересобрать и поставить магазин.

Проверить, что сервер отвечает, можно прямо в браузере:
`https://raw.githubusercontent.com/ВАШ_ЛОГИН/leapmarket-catalog/main/apps.json`

## Добавить новое приложение

1. Положить APK в `apks/`.
2. `python tools/build_catalog.py --repo ВАШ_ЛОГИН/leapmarket-catalog`
3. При необходимости положить иконку и вписать название с описанием.
4. Залить обновлённый `apps.json` и новую иконку в `main`.
5. Приложить APK к релизу `apps`.

Магазин подхватит приложение при следующем открытии или по кнопке обновления.

## Обновить версию приложения

1. Удалить из `apks/` старый APK, положить новый.
2. Запустить скрипт — он перепишет `version`, `version_code`, `size_mb`
   и `apk_url`, а название с описанием оставит как были.
3. Залить `apps.json` в `main`.
4. В релизе `apps` удалить старый файл и приложить новый.
5. На устройстве приложение попадёт во вкладку «Обновления».

Магазин считает версию новее, если `version_code` в каталоге больше того,
что установлено на устройстве. Поэтому `version_code` менять руками не нужно —
он берётся из самого APK.

## Из-за чего чаще всего не работает

- **Репозиторий приватный** — каталог не загрузится, магазин покажет ошибку сети.
- **Тег релиза не `apps`** — `apk_url` в `apps.json` будет указывать в пустоту.
  Другой тег задаётся ключом `--tag`.
- **Файл в релизе переименован** — ссылка в каталоге собирается из имени файла
  в `apks/`, имена должны совпадать.
- **Версия в каталоге старее установленной** — Android запрещает откат версий,
  установка завершится ошибкой «На устройстве установлена более новая версия».
- **Ветка не `main`** — задаётся ключом `--branch`.
